# Variable Listing Workbook

`inventory/variable_listing.xlsx` is the variable audit workbook for the SEG Dataverse harmonized/stable analysis datasets listed in `inventory/paper_analysis_datasets.csv`.

The build script treats the manifest as the source of truth. It does not glob the filesystem and it does not modify any source `.dta` files.

## Build Inputs

Run:

```bash
python inventory/build_variable_listing.py
```

By default, the builder reads `inventory/paper_analysis_datasets.csv`. To use an external manifest without copying it into the repo, pass:

```bash
python inventory/build_variable_listing.py --manifest /path/to/paper_analysis_datasets.csv
```

The builder keeps manifest rows with `analysis_handoff = 1` plus rows whose `absolute_dataset_path` is under one of these IEC stable locations:

- `/dartfs/rc/lab/I/IEC/seg/harmonized/`
- `/dartfs-hpc/rc/lab/I/IEC/seg/harmonized/`
- `/dartfs/rc/lab/I/IEC/seg/clean/`
- `/dartfs-hpc/rc/lab/I/IEC/seg/clean/`

The script fails loudly if `seg_correlates.dta` is missing from the manifest or is not selected by either `analysis_handoff = 1` or the stable path filter.

To audit the full manifest rather than only stable handoff rows, run:

```bash
python inventory/build_variable_listing.py --manifest /path/to/paper_analysis_datasets.csv --scope all
```

`--scope all-dta` scans every `.dta` manifest row. `--scope all` scans every manifest row. Stata files use Stata labels/storage metadata, CSV files use inferred pandas types, DBF/SHP files use GeoPandas attribute schemas, and non-tabular shapefile sidecars such as `.prj` and `.shx` receive a file-level placeholder row. Missing files are retained in the workbook as `__missing_file__` placeholder rows and logged.

Use `--workbook` and `--csv-dir` to write directly to a handoff location, for example `/dartfs-hpc/scratch/siddiqui/variable_listing.xlsx` and `/dartfs-hpc/scratch/siddiqui/seg_variable_listing/variable_listing_csv/`.

## Workbook Structure

`_index` lists one row per scanned dataset:

- `dataset_name`: dataset basename from the manifest.
- `absolute_dataset_path`: absolute IEC path read from the manifest.
- `n_obs`: total observations in the dataset.
- `n_vars`: total variables in the dataset.
- `file_type`: extension/type inferred from the manifest basename.
- `creator_script`: creator script from the manifest.
- `producer_script`: producer script from the manifest.
- `dataset_stage`: dataset stage from the manifest.
- `sheet_name`: Excel sheet name used for this dataset.

Each dataset sheet is long form, with one row per variable:

- `dataset_name`: dataset basename.
- `variable_name`: Stata variable name.
- `variable_rename`: proposed DDL-style replacement name, blank if the current name is acceptable.
- `variable_label`: Stata variable label, blank if none.
- `storage_type`: Stata storage type, such as `byte`, `int`, `long`, `float`, `double`, `str#`, or `strL`.
- `is_categorical`: `1` if a value label is attached, or if the variable is integer-typed with at most 20 unique nonmissing values.
- `levels`: semicolon-separated unique nonmissing levels for categorical variables, capped at 50.
- `value_labels`: semicolon-separated `code=label` pairs from the attached Stata value-label set.
- `n_missing`: count of numeric missing values or blank strings.
- `n_obs`: total observations.
- `pct_missing`: missing share rounded to three decimals.
- `used_analysis`: `1` when the variable is statically referenced by the dataset's `a/` consumer scripts; otherwise `0`.
- `used_analysis_scripts`: semicolon-separated `a/` scripts where the variable is referenced.
- `cleaning_flag`: manual review column.
- `rename_suggestion`: manual review column.
- `conflict_flag`: generated by `scan_variable_conflicts.py`.
- `remedial_note`: generated by `scan_variable_conflicts.py`.

## Manual Review Conventions

Set `cleaning_flag = 1` when the variable meaning is unclear or needs PI review. If `cleaning_flag = 1`, fill `rename_suggestion` with the proposed clearer name or a short note explaining what needs resolution. Use `variable_rename` for explicit DDL-style rename proposals that follow the lowercase snake_case, source-prefix, and `_id`/`_name` suffix guidelines.

`conflict_flag` is generated by the conflict scanner. Possible values are:

- `naming`: same variable name has incompatible storage or non-overlapping value-label code sets.
- `coding`: same variable name has different value-label mappings.
- `conceptual`: different variable names share the same normalized label and may be harmonizable.
- `label`: same variable name has inconsistent labels.
- `derivable`: variable name suggests it may be deterministically derived from another variable in the same dataset.

## Conflict Scan

Run after the first-pass workbook exists:

```bash
python inventory/scan_variable_conflicts.py
```

Pass `--manifest /path/to/paper_analysis_datasets.csv` to populate `used_analysis` and `used_analysis_scripts` from manifest `consumer_scripts`. Pass `--workbook`, `--csv-dir`, and `--analysis-dir` to operate on scratch copies.

The scanner writes a `_conflicts` sheet with:

- `variable_name`: affected variable name, or multiple names for conceptual conflicts.
- `datasets_involved`: semicolon-separated dataset basenames.
- `conflict_type`: one of `naming`, `coding`, `conceptual`, `label`, or `derivable`.
- `evidence`: compact diff or heuristic evidence.
- `proposed_change`: suggested harmonization action.
- `risk_note`: uncertainty or caveat.

The scanner also overwrites CSV mirrors under `inventory/variable_listing_csv/` so workbook contents can be diffed in git.

Identifier-only differences such as storage-type mismatches for `*_id`, `*_key`, `*_code`, `*_number`, `*_name`, `shrid`, `town`, `district`, `state`, and `eb_number` are suppressed from conflict flags when there is no value-label coding conflict. These are usually expected across different universes, vintages, or key files.
